# Candidate Knowledge / Learning Staging Reference

Status: REFERENCE ONLY — NO LIVE CROSS-ENGAGEMENT CANDIDATES IN CLEAN ROLE

Under RF v4.5, live ARCHITECT Learning Candidates belong in the **Engagement-owned store**, not in the clean ARCHITECT repository.

This directory remains only to document the legacy concept and candidate-content expectations.

## Rules

- A learning candidate is not canonical Expert Memory.
- ARCHITECT may create and refine candidates in a learning-enabled Engagement.
- ARCHITECT may mark `RECOMMENDED_FOR_ROLE_REVIEW` but may not self-assign `APPROVED_FOR_ROLE_REVIEW`.
- Only explicitly `APPROVED_FOR_ROLE_REVIEW` candidates are exported to Role Updater.
- Approval for review means "evaluate this", not "promote this".
- Raw Engagement evidence remains Engagement-side; exports use de-identified summaries/opaque refs.
- Role Updater, mandatory System Validation and RF Owner release approval govern any resulting clean-ROLE change.
- Do not persist live candidate state here as a substitute for an Engagement candidate store.
